## 0. 文档用途与使用方式

- **对 codewhale**:按"第 5 节 实现规划"逐阶段实现核心算法层(纯 Python)。
- **对 Claude Code**:进入 `factor_loop_engine/` 目录后,让 Claude Code 阅读本文件,即可从"阶段 1"开始执行同一套任务;最终在 Claude Code 里用 `/loop` 组装成无人值守闭环。
- **关键原则**:核心算法层(算子/演化/回测/FSA/检查点)是纯代码,与 Loop 编排层物理分离——前者任何 Python 环境可跑,后者依赖 Claude Code 的 `/loop`、skill、sub-agent、hook。

## 1. 项目目标

把因子挖掘的"生成—回测—筛选"流程封装为**定时调度、断点续跑、无人值守**的自动化闭环:

- 大模型评判因子经济学含义,避免无意义统计因子
- 自定义因子优化方向,而非只看单维度指标
- 可扩展到另类/高频数据

**最终产出**:
1. 核心算法层 Python 代码(本地可独立跑通单轮)
2. 回测引擎对接接口(真实引擎由用户提供后接入)
3. 对接 Claude Code 的 `/loop` 配置指南(skill / sub-agent / hook)

---

## 2. 系统全景

三步闭环流水线:**生成 → 审查 → 验证**

| 阶段 | 职责 | 实现方式 |
|---|---|---|
| 生成 | 五种策略产生候选表达式 | 演化引擎 + LLM 机制引导 |
| 审查 | 规则过滤 + LLM 精判 | 四道硬过滤 + 抽样精判 |
| 验证 | 回测 + 多维过滤 + 去重 | 硬编码回测(用户提供)+ 11 项过滤 |

**核心设计哲学**:生成端**绝不接触回测指标**(防 Goodhart 定律——指标一旦成为优化目标就失效)。生成与验证由独立子代理承担,通过临时 JSON 文件单向传递,物理隔离。

**三层架构**:
- Loop 编排层(Claude Code 专属):`/loop` 每 5 分钟触发
- LLM 子代理层:生成端(机制假设)、审查端(LLM 精判)
- 硬编码工程层:算子库、表达式树、演化算法、回测、FSA、检查点

## 3. 研报完整拆解(9 个模块)

### M1. 算子库(14 种)+ 表达式树

表达式以**树**表示:叶子 = 数据字段,内部节点 = 算子,递归生成,**最大深度 4 层**(实测平均 3.6 层)。

| 算子 | 类型 | 窗口/参数 | 说明 | 示例 |
|---|---|---|---|---|
| `ma` | 时序 | n: 3~250 | 移动平均 | `ma(overnight, 220)` |
| `std` | 时序 | n: 5~120 | 滚动标准差 | `std(zscore(volume), 66)` |
| `max` | 时序 | n: 5~120 | 滚动最大值 | `max(high, 60)` |
| `min` | 时序 | n: 5~120 | 滚动最小值 | `min(low, 30)` |
| `roc` | 时序 | n: 3~60 | 变化率 | `roc(close, 20)` |
| `delta` | 时序 | n: 3~60 | 差分 | `delta(amplitude, 60)` |
| `skew` | 时序 | n: 10~120 | 滚动偏度 | `skew(ret, 60)` |
| `rank_ts` | 时序 | n: 5~120 | 时序排名 | `rank_ts(volume, 20)` |
| `add` | 逐元素 | 无 | 加法 | `add(amplitude, overnight)` |
| `sub` | 逐元素 | 无 | 减法 | `sub(down_shadow, overnight)` |
| `mul` | 逐元素 | 无 | 乘法 | `mul(close, log_mv)` |
| `div` | 逐元素 | 无 | 除法 | `div(ma(overnight,118), min(down_shadow,66))` |
| `zscore` | 截面 | 无 | 截面标准化 | `zscore(overnight)` |
| `rank_cs` | 截面 | 无 | 截面排名 | `rank_cs(log_amount)` |

嵌套示例:`zscore(div(ma(close,20), std(sub(high,low),10)))`(近20日价格中枢 / 日内波动稳定度,再截面标准化)。

### M2. 数据字段(9 原始 + 10 派生)

> 数据源:阿里云 OSS bucket `ys-datalake`,DuckDB httpfs 内网直读(详见 `OSS取数说明.md`)。
> ⚠️ OSS 日频表 `stock/daily_bar/year=*/data.parquet` 的价格为**未复权原始价**,必须先做前复权处理(见 2.2)。

#### 2.1 OSS → 研报 字段映射(口径已确认)

| 研报字段 | OSS 来源 | 处理方式 |
|---|---|---|
| `open/high/low/close` | daily_bar.open/high/low/close | **原始价 → 必须前复权**(见 2.2) |
| `pct`(涨跌幅%) | **自算** | `(adj_close / shift(adj_close,1) − 1) × 100`,用前复权价 |
| `volume` | daily_bar.volume | 原样(**成交量不复权**) |
| `amount` | daily_bar.**total_turnover** | 直接映射,改名为 amount |
| `mv`(市值) | **自算** | `adj_close × shares.free_circulation` = **自由流通市值** |

**已确认的 4 项字段决策**:
1. `amount` 直接用 OSS 的 `total_turnover`
2. `pct` 自算(用前复权 close 的变化率,非原始价)
3. `mv` 用**自由流通市值** = adj_close × `shares.free_circulation`(量化中性化常用)
4. 所有价格类字段**统一前复权**后再算派生字段

#### 2.2 前复权统一处理(所有价格字段必做)

复权因子来自 `stock/ex_factor/data.parquet` 的 `ex_cum_factor`(累计复权因子)。对每只股票每个交易日:
```
adj_price[t] = raw_price[t] × ex_cum_factor[t] / ex_cum_factor[最新]
```
- `open/high/low/close` 统一前复权 → `adj_open/adj_high/adj_low/adj_close`
- `volume`、`total_turnover` **不复权**(量/额不随除权调整)
- `mv` 用前复权 close 计算
- `overnight` 的"昨收"用 `shift(adj_close, 1)`,**不用 daily_bar.prev_close**(prev_close 是原始价,单独对其复权需按 T-1 对齐因子易错;shift(adj_close) 等价且干净)

#### 2.3 派生字段公式(全部基于前复权价,严格统一)

| 字段 | 公式 | 说明 |
|---|---|---|
| `intraday` | `adj_close/adj_open − 1` | 日内收益 |
| `overnight` | `adj_open/shift(adj_close,1) − 1` | 隔夜收益(昨收=前复权收盘 shift1) |
| `amplitude` | `(adj_high − adj_low)/adj_close` | 日内振幅 |
| `up_shadow` | `(adj_high − max(adj_open, adj_close))/adj_close` | 上影线占比 |
| `down_shadow` | `(min(adj_open, adj_close) − adj_low)/adj_close` | 下影线占比 |
| `hl_ratio` | `(adj_close − adj_low)/(adj_high − adj_low)` | 收盘价区间位置 |
| `ret` | `pct/100`(即 adj_close 收益小数) | 收益率 |
| `log_volume` | `log(volume + 1)` | 对数成交量(volume 不复权) |
| `log_amount` | `log(total_turnover + 1)` | 对数成交额 |
| `log_mv` | `log(adj_close × free_circulation + 1)` | 对数自由流通市值 |

⚠️ **数据层三大核对项**(任一错则因子全错):
1. 前复权因子 `ex_cum_factor` 必须按 `order_book_id + date` 正确对齐到每日
2. `overnight` 用 `shift(adj_close)` 而非 `prev_close`
3. `mv` 的 `free_circulation` 必须按 `order_book_id + date` 对齐 `shares` 表

### M3. 生成引擎:五维演化(核心算法)

**默认预算分配**(可动态调整):

| 操作 | 占比 | 说明 |
|---|---|---|
| 变异 mutate | 25% | 替换表达式树中的叶子/子树,保留骨架换信号源 |
| 交叉 crossover | 25% | 两个高分因子交换子树 |
| 参数扰动 perturb | 15% | 结构不变,微调窗口(动量引导,见 M4) |
| 随机探索 random | 15% | 纯随机生成,防过早收敛 |
| LLM 机制引导 llm | 20% | 13 机制族假设驱动(见 M5) |

**冷启动**:全部随机生成,确保初始广度;因子库积累后切演化模式(也可直接以现有因子池进入演化)。

**动态预算**:
- 已有因子附近仍持续产高分 → 上调变异 + 参数扰动
- 高 IC 候选大量触发相关性去重 → 上调随机探索 + 机制引导
- 某机制族长期缺候选 → 机制引导优先补该方向
- 多机制已覆盖但入库率持续降 → 上调交叉
- 本质:exploration / exploitation 动态平衡

**种子选择优先级**:从**已入库因子**(过 11 项筛选,质量更高)选父本,以 50% 概率执行变异或交叉;优于宽泛因子库采样。

### M4. 参数扰动优化算法

三步:

**1. 梯度估计**(加权最小二乘):对同字段因子的历史记录,拟合
```
Sharpe(n) ≈ w0 + w1 × n
```
- 斜率 `w1` 即梯度方向(正→增大窗口有利,负→减小有利)
- **高斯核加权**:距当前参数越近的历史点权重越大,只用局部邻域
- 同字段历史不足 → 梯度退化为 0,扰动暂停

**2. 动量平滑**(指数移动平均):
```
m_t = β · m_{t-1} + (1 − β) · g_t      # β = 0.7
```
新信息按 30% 融入历史方向,避免单次噪声改向。

**3. 自适应步长**(Adam 风格):每个参数独立追踪历史波动幅度,波动大→缩小步长,波动小→放大步长。

### M5. LLM 机制引导:13 个机制族

分**时序 / 截面**两大类,每族下有研究原型。机制引导 = 统计因子库**未覆盖**的族 → 优先从该族选原型 → 生成自然语言假设 → 转表达式。

**时序类(8 族)**:
- 趋势与动量:趋势启动 / 趋势延续 / 动量衰竭
- 反转与均值回归:短期过度反应 / 抛压耗尽后修复 / 突破失败后反转
- 边界突破:上沿突破并站稳 / 下沿跌破并延续 / 回踩确认后再启动
- K 线与日内结构:实体强度与收盘位置 / 影线压力与价格拒绝 / 多日转折结构
- 跳空与隔夜定价:缺口延续 / 缺口回补 / 隔夜与日内方向切换
- 波动压缩与释放:波动压缩 / 扩张后修复 / 区间能量积累与释放
- 波动状态:高波动状态信号 / 低波动状态信号 / 波动状态切换
- 回撤与修复:渐进式回撤 / 深度回撤后恢复 / 反弹失败后二次下跌

**截面类(4 族)**:
- 相对强弱与定价偏离:市场相对动量 / 同期极端收益反转 / 相对价格位置偏离
- 截面风险收益错配:低波动中的相对强势 / 高波动但收益补偿不足 / 收益与尾部风险排序背离
- 截面波动与振幅异常:相对低波动溢价 / 异常振幅扩张 / 波动排名突变
- 截面分化与一致性:收益分化扩张 / 波动分化加剧 / 市场一致性上升

> ⚠️ 数量说明:研报正文写"13 个机制族",但**图表 7 实际只列出 12 个顶层族**(8 时序 + 4 截面),这是研报本身的小幅出入。**实现以图表 7 的 12 族为准**——它已完整覆盖研报列出的所有研究原型,无需硬凑 13。

**机制引导 vs 随机探索**:前者用金融机制约束生成范围,提高与研究意图一致性;后者保广度。两者并存,避免走向"纯随机"或"纯先验"任一极端。

### M6. 审查阶段(4 道硬过滤 + LLM 精判)

**硬过滤**:
1. 外层截面算子自动退化
2. 同质算子简化
3. **跨量纲运算拒绝**(如 `add(close, volume)` 价格 + 成交量)
4. 最小复杂度门槛(如单算子单叶子、深度 ≤2 直接拒)

**LLM 精判**:随机抽 5 个候选,检查表达式边界条件是否合理。

### M7. 验证回测(硬编码,11 项联合过滤)

**回测设置**(本项目最终参数,见第 4 节决策):
- 区间:**2018-01-01 ~ 2025-12.31**
- 股票池:A 股全市场
- 换仓:5 日
- 成本:单边千一
- IC:Spearman 秩相关,5 日换仓频率

**11 项过滤**(⚠️ 已按"每年都过"决策泛化,适配 2018-2025 区间):

| # | 条件 | 说明 |
|---|---|---|
| 1 | `|IC| > 0.03` | 统计显著性 |
| 2 | **每一年超额 > 0**(2018…2025 各年) | 年度稳定性(每年都过) |
| 3 | 区间整体年化超额 > 0 | 整体有效性 |
| 4 | 区间整体夏普 > 0.5 | 风险调整收益 |
| 5 | 最后一年(2025)夏普 > 0.5 | 近期质量 |
| 6 | Calmar > 1.0 | 回撤控制 |
| 7 | 近 9 月超额 > 0(滚动,相对末日) | 近期持续性 |
| 8 | 近 12 月超额 > 0(滚动) | 近期持续性 |
| 9 | IC 序列相关性 < 0.70(与已入库因子) | 独立性去重 |
| 10 | 结构去重(FSA 骨架 + 参数变体上限) | 多样性 |
| 11 | 失败模式库排除 | 已证无效不再测 |

> 原研报用 2025/2026 具体年份;本项目区间为 2018-2025,故"每年超额>0"指 2018 至 2025 每一个完整年度超额均 > 0。这是**最严**的稳定性门槛。

**达标 → 入库 + 更新检查点**。

### M8. 失败规避体系(事前-事中-事后)

- **事前**:数据驱动特征分布(存活因子的字段/窗口分布引导随机生成)、**FSA**、失败模式库
- **事中**:M6 审查四过滤
- **事后**:M7 的 11 项

**FSA(频繁子树规避)**——抑制结构趋同:
1. **抽象化**:`div(ma(close,20), ma(close,10))` → `div(ma(FLD,N), ma(FLD,N))`(参数→N,字段→FLD,只留骨架)
2. **频率统计**:支持度(该结构在因子库占比)> **15%** 且出现 ≥ 2 次 → 进禁止列表
3. **同骨架参数变体上限 5 个**:防止同结构换参数刷数量
4. 命中禁止列表 → 拒绝并强制重新生成

> 研报实证:450 轮后 overnight 骨架超 15% 被冻结,迫使搜索转向 down_shadow / hl_ratio,入库结构成功扩散。阈值 15% 实践良好。

### M9. Loop 工程层(Claude Code 专属)

五类构件:

| 构件 | 作用 | 实现 |
|---|---|---|
| 定时调度 | 每 5 分钟触发一轮 | Claude Code `/loop` 命令 |
| 检查点 | 跨会话连续性、断点续跑 | 原子写入文件(见下) |
| Skill 封装 | 项目背景/算子/参数/约束固化,自动加载 | `./skills/` 目录 |

**检查点文件内容**(原子写入):

- 入库因子的完整信息(含 IC 序列快照、多维评分)
- 动量追踪器状态(M4)
- 迭代计数

**三道安全防线**:迭代上限 / 高风险操作人工确认 / 全流程日志。

**构建次序**:先手动跑通单轮 → 封装 Skill → 组装 Loop → 开定时调度,每阶段验证稳定才进下一阶段。

## 5. 实现规划(7 阶段)

### 阶段 1:数据源探索
- **做什么**:读现有 `duckdb_daily_bar.py` / `oss.py` / `data_loader.py`,搞清 OSS 连接方式(凭证/endpoint);试连拉一小段日频行情;核对字段语义
- **产出**:字段映射表 + 派生字段公式表(本文档第 3.2 节的落地确认版)
- **验收**:能从 OSS 取到 2018-2025 的 close/high/low/open/volume/amount/mv,字段含义与研报一致
- **依赖**:OSS 凭证可用

### 阶段 2:字段层
- **做什么**:实现数据加载 + 派生字段计算(严格按公式),本地缓存常用数据
- **产出**:`data_loader.py`(OSS 取数 + 本地缓存)、`derived_fields.py`(派生字段)
- **验收**:派生字段(尤其 overnight 隔夜)与人工抽样核对一致
- **关键风险**:复权与 shift 口径

### 阶段 3:核心算法层
- **做什么**:表达式树 + 14 算子、五维演化引擎、参数扰动(梯度+动量+Adam)、FSA、审查四过滤、检查点原子读写
- **产出**:对应模块代码 + 单元测试
- **验收**:算子计算正确性、树生成/解析、演化保结构、FSA 抽象与禁止命中、检查点写/恢复

### 阶段 4:LLM 层
- **做什么**:13 机制族引导生成 + 审查精判,封装为可切换 provider(DeepSeek-v4 生成 / 智谱 GLM 审查)
- **产出**:`llm_provider.py`(统一接口)+ 机制族 prompt 模板
- **验收**:能切 provider;机制引导能产出合法表达式;审查能拦截越界表达式

### 阶段 5:回测接口

## 8. 对接 Claude Code 的方案概要(阶段 7 详化)

最终把核心算法层包装成 Claude Code 的 Loop 闭环:

- **Skill 封装**:把算子定义、字段、过滤阈值、演化预算、工程约束写进 `./skills/factor_mining.md`,agent 每轮自动加载,失败经验追加沉淀
- **Sub-agent 拆分**:`generate.py`(加载因子库+演化+输出候选)、`review.py`(规则粗筛+LLM 精判)、`evaluate.py`(回测+过滤+去重+更新库),三者通过临时 JSON 单向传递,**生成端不接触任何回测指标**
- **Loop 调度**:用 Claude Code `/loop` 每 5 分钟触发 `loop_orchestrate.py`,迭代上限 + 连续无新因子时动态预算
- **Hook**:在 `settings.json` 配 `PostToolUse`,每轮输出因子库状态摘要(已测试/已保存/Top 因子)
- **检查点**:`checkpoint.json` 原子写入,任意中断可断点续跑

> 详细配置步骤在阶段 7 代码就绪后,写入 `claude_code_integration.md`。

## 10. 风险与注意事项

1. **过滤年份已泛化**:原研报 2025/2026 → 本项目"2018-2025 每年超额>0",更严,入库因子会更少但更稳
2. **无真实回测引擎**:核心流程先用 mock 验证;因子真实好坏要等回测引擎接入才能判定
3. **OSS 连接**:需确认现有代码的凭证/连接方式在当前环境可跑通
4. **派生字段口径**:`overnight` 隔夜收益的"昨收"必须用前复权 shift1,复权处理不一致会全错——**数据层第一优先核对**
5. **DeepSeek-v4 API**:接入方式与计费需用户确认;provider 封装保证可切换
6. **"每年都过"的副作用**:2018-2025 含多轮牛熊切换(2018熊、2019-20牛、2021-22震荡、2024-25反弹),全程每年超额>0 极严,可能需要后续放松为"近 N 年"
